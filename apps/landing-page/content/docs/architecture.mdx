The runtime is split into planes. Each plane has one owner, and money only moves through one planning path that ends at your wallet.

## Planes and the services behind them

| Plane    | What it does                                                                                      | Where it runs today                                                         | Status                                                                                                          |
| -------- | ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Data     | Collects prices, sentiment and wallet positions every day                                         | `alpha-etl`, hosted                                                         | <StatusBadge capability="market-signals" />                                                                     |
| Strategy | Evaluates the reference strategy into an advisory target and decision packet; runs backtests      | `analytics-engine`, hosted                                                  | <StatusBadge capability="reference-strategy" />                                                                 |
| Planning | Turns a request into prepared transactions                                                        | `account-engine` plan orchestration with `@zapengine/intent-engine`, hosted | <StatusBadge capability="deposit-plans" /> deposits · <StatusBadge capability="rebalance-plans" /> rebalances   |
| Adapters | Encode already-decided actions for Morpho, GMX v2, Hyperliquid and LI.FI; never choose a strategy | `packages/intent-engine/src/protocols/`                                     | <StatusBadge capability="adapter-boundary" />                                                                   |
| Check    | Approval caps, minimum received, Tenderly simulation                                              | `intent-engine` validators, run by plan orchestration                       | <StatusBadge capability="pre-sign-checks" />                                                                    |
| Signing  | Shows the plan and asks your wallet to sign                                                       | The app and your wallet                                                     | <StatusBadge capability="wallet-signing" />                                                                     |
| Notify   | Checks for drift and tells you                                                                    | The Mac app (`apps/desktop`), not distributed yet                           | <StatusBadge capability="local-drift-check" />                                                                  |
| Record   | Keeps a public record of outcomes                                                                 | Daily IPFS snapshots; one rule as Vyper bytecode on Arbitrum Sepolia        | <StatusBadge capability="snapshot-chain" /> snapshots · <StatusBadge capability="verifiable-rule" /> rule check |

`analytics-engine` decides allocation and never builds transactions. `account-engine` owns identity and plan orchestration, and identity code never plans money movement. The app confirms, signs and broadcasts prepared transactions; it does not rebuild plans on its own.

## Hosted today, your machine later

Every plane above that runs today runs on Zap Pilot-hosted services. Running strategy evaluation and planning on hardware you control is planned <StatusBadge capability="self-hosting" />. Automation grows in steps, and each step waits for the safeguards of the one below it:

| Level | What happens                                                                 | Status                                         |
| ----- | ---------------------------------------------------------------------------- | ---------------------------------------------- |
| L0    | Manual: you read the decision and start a deposit yourself                   | <StatusBadge capability="deposit-plans" />     |
| L1    | Notify: the Mac app checks for drift and tells you; it never signs           | <StatusBadge capability="local-drift-check" /> |
| L2    | One-tap plan: a strategy target becomes a rebalance plan you review and sign | <StatusBadge capability="rebalance-plans" />   |
| L3    | Policy-bounded: every plan is checked against limits you set before signing  | <StatusBadge capability="policy-engine" />     |
| L4    | Unattended inside scoped on-chain permissions you can revoke (later)         | <StatusBadge capability="unattended-runs" />   |

## Trust boundaries

- **Zap Pilot servers.** If a server is wrong or down, the result is bad advice or no plan. A server cannot move funds by itself: every plan still needs your signature, so check what your wallet shows before you sign.
- **Your wallet and Privy.** Your wallet holds the keys and signs. Privy is an onboarding rail for embedded wallets; Privy wallets also sign an EIP-712 intent bound to each batch.
- **The Hyperliquid agent key.** Created and stored on your device, never on a Zap Pilot server. You approve it once, and that approval may not expire, so treat the device like a wallet.
- **Third-party venues.** There is no Zap Pilot vault or custody contract, but Morpho vaults, GMX GM pools and Hyperliquid HLP are pooled protocols with their own curator, oracle, counterparty and smart-contract risks. HLP deposits are locked for a period set by Hyperliquid.
- **LI.FI.** Routes swaps and bridges. Every route must quote a minimum received within 1% of its estimate, but bridges add their own risk.
- **Tenderly.** Simulates each batch before it is returned. A failed simulation blocks the plan; a provider outage does not.
- **Data sources.** Prices, sentiment and positions come from public providers (including DeBank, the Hyperliquid API and CNN's Fear & Greed index). Bad data produces bad advice, which is one more reason the signature stays with you.
