The track record has three parts. None of them is a live account's results.

## Daily backtests

<StatusBadge capability="reference-strategy" qualifier="backtest" />

The charts on the [track record page](/track-record) default to the reference strategy's backtest, recomputed every day over a rolling 500-day window and compared with [DCA Classic](/docs/track-record/dca-classic-v1). The results are hypothetical; the [backtest method](/docs/track-record/dma-fgi-portfolio-rules-v1#backtest-method) lists its assumptions.

## Snapshot chain

<StatusBadge capability="snapshot-chain" />

Every day a snapshot of one reference address — its positions, NAV and performance — is published to IPFS. Each snapshot links to the previous one by CID, so the history is tamper-evident. Snapshots are **unsigned** today: no official signer is configured, so the chain shows that the record was not edited after publication, not who published it. Switch the track record page to **Snapshots** to load it.

## On-chain rule check

<StatusBadge capability="verifiable-rule" />

The [Verifiable Strategy calculator](/docs/track-record/verifiable-strategy) recomputes one recorded cross-down exit with public Vyper bytecode on Arbitrum Sepolia. It covers one of six rules and is not the production strategy.

## Verify

The verification CLI walks the published snapshot chain:

```bash
pnpm track-record:verify
```

It validates the schema, recomputes performance metrics and checks each snapshot's content hash. Until snapshots are signed, it reports the official signer as `none`.
