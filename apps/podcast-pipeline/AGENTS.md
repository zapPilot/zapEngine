# Gotchas

- **Chinese script contract (2026-09-30).** `zh-Hant` is the main Chinese lane ID, not a character-form promise: new titles, narration, TTS/subtitles, Rednote copy and classroom explanations use Simplified Chinese. Threads copy and the Zap Pilot-facing `/episodes` API responses convert human-visible Chinese text to Taiwan Traditional Chinese at their publication/display boundaries; teaser and in-app video subtitles retain the main video’s Simplified subtitles. Never add Traditional conversion to ingest, persistence, TTS, or video generation. Preserve scraped articles verbatim. Simplified normalization must use `convertTextToZhCN` (`t→cn`); never apply `twp→cn` or `tw→cn` to Simplified text because they corrupt source vocabulary. Renaming the lane is a separate migration.

- `supabase/migrations/` and `supabase/schema.sql` are a frozen snapshot as of migration 035; parity tests read them in place. Current schema truth is the live database plus root `supabase/migrations/` (see CONTRIBUTING.md "Adding a database migration").
- **Telegram env vars are namespaced.** This service uses `PIPELINE_TELEGRAM_*` (bot token, webhook secret, allowed user IDs) deliberately so it does not collide with `apps/account-engine`'s `TELEGRAM_*` bot. Do not introduce unprefixed `TELEGRAM_*` vars here — they would be read by both processes.
- **Webhook is fire-and-forget.** `/telegram/webhook` returns 200 immediately and then runs `runIngestPipeline` in the background. Adding `await` on the pipeline call from the handler breaks Telegram's webhook timeout contract — keep new long-running work behind the same fast-ack pattern.
- **Telegram ingest is a durable bounded queue, not one task per webhook.** Submissions persist to `podcast_ingest_jobs`, then the pump claims at most `PODCAST_INGEST_MAX_CONCURRENT_JOBS` (currently 4) live ingests across the whole deployment. The claim RPCs enforce the same ceiling under a transaction advisory lock so blue/green overlap cannot multiply it. Keep queued rows unclaimed until capacity exists; `processing` must mean a job is actually consuming an ingest slot. Recovery is silent at start — do not resend the submission acknowledgement after a crash — and a Supabase outage may fall back to local work only through the same bounded four-slot admission path.
- **Video renders live in their own process.** `src/index.ts` serves HTTP and runs ingest; `src/worker.ts` runs the video worker, and they deploy as separate Fly process groups (`app` on shared CPU, `render` on dedicated CPU — see README). `bootstrap()` does not start a worker unless asked (`startVideoWorker: true`). Do not move rendering back into the API process: ffmpeg starves the event loop until `/health` times out and Fly drops the instance from the proxy pool. `heavyWorkCoordinator` still keeps ingest off the CPU while any video runs in a single-process setup, but it cannot coordinate across the two groups — that separation is the point, and it no longer caps how many videos run. That cap lives in `src/services/render-admission.ts`: `renderJobCapacity(os.availableParallelism())`, bounded by `RENDER_MAX_CONCURRENT_JOBS`, plus at most one visual job. It is derived from the vCPU count rather than the fly.toml shape because a job past the core count does not run in parallel — it queues for a core that does not exist while still holding its own memory, which is what OOM-kills a small machine. On the current `performance-1x` render shape that means strictly one job, and `/proc/meminfo` is never read at all; the `MemFree` admission and the second slot only ever open on a 2-vCPU machine. Keep the visual cap at one, because Brave's image API returns a terminal 429 that degrades image quality rather than failing, and keep an unreadable `MemFree` failing closed to one job. The worker may only report `'empty'` when nothing is in flight: `src/worker.ts` exits the process on it, which would kill a render holding the other slot. `drain()` and `stop()` are not interchangeable — `drain()` stops claiming and waits for what is in flight, `stop()` aborts it — so the uptime guard must `drain()` before `shutdown()`, never the reverse. **Do not re-propose opening the second slot on `performance-1x` without re-reading the 2026-09-21 check-in in README.md's Deployment section first**: it measured two concurrent encodes at 2608 MB against this shape's 2 GB (a certain OOM), and the realistic saving from overlapping the ~19% pre-encode window is under $1/month.
- **Resumability is load-bearing.** Fly keeps one `app` machine running so the webhook is always reachable, but deploys and restarts can still interrupt ingest. Each pipeline stage commits its result to Supabase before advancing, and the next submission of the same URL resumes from the latest committed stage. New pipeline stages must persist their output before yielding, or resume will silently lose work.
- **The render group is on demand — that is its only mode — and its wake-up test mirrors the claim RPCs.** `src/worker.ts` exits `0` on an idle queue unconditionally, and `src/services/render-capacity.ts` (in the always-on API process) starts the machine again. `readFlyMachinesConfig()` needs exactly the platform's `FLY_APP_NAME` plus `PIPELINE_FLY_API_TOKEN` (Infisical prod → `env:sync` → Fly). **Never reintroduce a feature flag or an always-on fallback here**: a missing token on Fly has to stay a boot-time configuration error, because the fallback that was deleted did nothing at all once the machine had already stopped itself — renders stalled silently from 2026-08-24 to 08-26 behind one boot log line. `evaluatePendingRenderWork` deliberately reproduces the `WHERE` clauses of `claim_episode_video_v2` / `claim_episode_video_visual_v2` — the `visual_version` fence, the completed-visual join, the attempt/backoff limits, and expired-lease `processing` rows. **Change the claim RPCs and this test together.** Looser here means the machine wakes, claims nothing and idles out on a loop; tighter means jobs sit on a stopped machine that nobody ever starts. Rows in `processing` past their lease are only reaped inside the claim RPCs, which is why they count as pending work rather than as work in progress.
- **`exit(0)` is what stops the render machine.** It works because the `render` group's restart policy is `on-failure` (declared explicitly in `fly.toml`). Switching it to `always`, or handling the idle path with a non-zero exit, turns the cost saving into a restart loop. Two paths reach it: an idle queue, and `MAX_UPTIME_MS` — the backstop for the case the idle exit structurally cannot cover, a poll that keeps throwing and therefore never reaches `onPollResult` with `'empty'`. The uptime path drains rather than aborting, so it costs one extra boot and never a render.
- **The cost ledger must never be able to fail the pipeline.** `recordPipelineRun` (`src/services/ops-ledger.ts`) swallows every error into one `[ops-ledger]` line plus a Sentry `warning` and resolves. Do not let a ledger write throw into ingest or a render — the money was already spent by the time it runs. Warning rather than silence is the other half of that rule: a ledger that quietly never writes looks exactly like a pipeline that never ran.
- **`fly.toml`'s render machine and `RENDER_MACHINE_SHAPE` change together.** Fly gives the worker no runtime signal for the machine it is on, so the shape is a constant in `src/services/ops-ledger.ts` and `ops-ledger.test.ts` parses `fly.toml` to prove they still agree. Resizing the `render` group also needs a new `ops.cost_rates` row, because a different shape is a different `metric_key`. Insert it and leave the old key's row **open**: it prices every render already in the ledger, migrations deploy ahead of the Fly release (`ci.yml`), and closing it would price the deploy window at null. Only a price correction to the _same_ shape closes an `effective_to` and opens another. Never edit a rate row in place, and never rewrite the key inside an already-applied migration — the file would stop describing the database, and the code would resolve against a key production does not have.
- **R2 upload retries live in `storage.ts`, and the SDK's warning about them lies.** `@smithy/core` refuses to retry any request whose body is a `Readable`, so `putObject` runs its own seven-attempt loop opening a fresh `createReadStream` each time. `An error was encountered in a non-retryable streaming request.` is printed by the SDK for **every** error on a stream body, _before_ any retry strategy is consulted — it is not evidence that the local loop did or did not run. The discriminator is the `[r2] put:retry` line, which carries `attempt`/`maxAttempts`; a failed upload step with **zero** of those lines means the classifier is wrong, not the budget. Keep the jitter (four uploads fail in lockstep without it) and keep the 8 s per-sleep ceiling below `kill_timeout = '30s'`, or a deploy will SIGINT the process inside a sleep it never wakes from. **Do not answer a longer R2 outage by lowering `R2_PUT_CONCURRENCY`** — a server-side 500 is not caused by four in-flight PUTs, and past ~30 s the answer is the resumability above, not a bigger budget.
- **Supabase schema is `from_fed_to_chain`, not `public`.** New queries must respect `SUPABASE_DB_SCHEMA` — defaulting to `public` will hit the wrong tables.
- **`social:daemon` is the canonical social production loop.** It runs on the local Mac because X/Rednote depend on persistent browser sessions. One daemon owns completed-localization discovery, durable enqueue/scheduling, platform publishing, standardized metric snapshots (`1h` / `6h` / `24h` / `72h` / `7d`), experiment reporting. Durable post/job identity remains `(episode, platform, language)` for duplicate protection, but the release/scheduling transaction boundary is `episode_id`; see the non-negotiable invariant below. Do not split metrics or publishing into required companion processes. `social:publish` and `social:metrics` are break-glass/debug commands only. `apps/control-center` is a read-only optional UI and must stay lifecycle-independent so a dashboard port failure can never stop publishing or metrics. Preserve the durable first-start anchor, DB lease/owner fencing, and the rule that missed early metric windows are not backfilled with later observations.
- **The publisher's `og:image` is the cover AND the first content scene — one image, not two.** This is a CTR invariant: the thumbnail a viewer clicks and the first content frame must resolve to the same source URL. `leadCoverOrderedArticleImages` (`src/services/video/visual-asset-planner.ts`) pins the `og:image` to the first content scene by reading `origin`; body images are aligned separately. The plan records what scene 0 rendered in `provenance.leadCoverImageUrl`, and `prepareVideoCover` reads that field without scraping. Never reintroduce a scene-0 exclusion. Decorative, missing or unrenderable OG covers fail the visual job; they do not enter the ordinary image ladder.

- **A concept card is a last resort, not a search result.** `resilient` mode generates an English concept card (`src/services/video/generated-slide.ts`, `provider: 'generated-slide'`) only after every v9 photo rung of the ladder for a scene is exhausted, and only up to `MAX_GENERATED_SLIDE_RATIO` of the content scenes. This was a 2026-09 product decision that replaced "one unphotographable scene fails the whole episode". The same decision has since removed the identity hard gate and widened reuse deliberately — a scene may now take an image from another subject's pool, and entity mention is only a ranking bonus — so a card is the last rung of a much longer ladder than it used to be; the numeric grounding of the card copy is unchanged. Do not let slides enter subject pools or reuse candidates, never put the narration sentence on the card (captions already speak it), and keep the slide copy path fail-open (deterministic copy) while the surrounding planner stays fail-closed once the cap is hit.
- **A visual subject is dropped alone; the catalog is never thrown away for one bad subject.** `materializeVisualSubjectCatalog` (`src/services/video/storyboard/search-intents.ts`) drops a compact LLM subject that is ungrounded, an abstract/non-visual category (`isGenericVisualSubjectName`, `subject-catalog.ts`), `type: other`/unknown, or title-only, records it in `subjectCatalog.droppedSubjects`, and repairs the primary from the survivors. Short names follow the same rule: a one-character name is valid only as one ASCII letter that the episode writes standalone (`X`), and a bad alias or identity hint is removed alone and recorded in `subjectCatalog.repairedSubjects`. Never lengthen, truncate or invent a name to get past a schema bound; `X` stays `X` and is never `X Corp`. Structural catalog errors receive readable feedback for up to three attempts and then fail the visual job. Deterministic photographic query generation has been removed. Eligibility is a **visual-anchor** rule, not named-entity-only: recognizable named places such as Wall Street / White House / 中南海 / Silicon Valley are valid, and a concrete common noun such as GPU, data center, server rack, factory, robot, or mining rig may be `type: object` when it is materially central to the story or scene. Broad abstractions such as AI, technology, markets, finance, innovation, or governance remain generic and must not become searchable anchors. Inside a scene, anchors sort by how specifically they identify something — person, then named entity, then `object` — because the first subject is the Brave query and the entity cap trims from the back. Queries contain one name and an optional 1–3-word English identity qualifier, never people/actions/settings/photographic style. A null qualifier permits a bare unambiguous name; absent qualifiers use the first safe identity hint. Do not reintroduce a throw on a single ungrounded subject, do not turn every noun into an anchor, and do not answer a bad episode by adding a real named entity or useful concrete anchor to the generic deny list.
- **The Brave request budget is per episode, and exhausting it degrades quality instead of failing.** `MAX_PRIMARY_SUBJECT_SEARCHES` (5) + `MAX_TARGETED_SUBJECT_SEARCHES` (3), capped at `MAX_BRAVE_REQUESTS_PER_EPISODE` (8), bound one visual attempt; a retry rebuilds the pool under the same ceiling. A subject that never got a search does not raise — its scenes fall through to an identity-compatible cross-subject pool, then reuse, then a concept card. The final quality gate can still reject excessive cross-subject fallback. So a video whose images look weak or repetitive is at least as likely to have been budget-starved as mis-searched, and `imageSearch.budgetExhausted` plus each scene's `fallbackReason` is what tells the two apart. Raising the caps costs real money per episode; do not raise them to fix one bad episode.
- **Under `resilient` mode a provider outage looks like a quality problem, not an incident.** A Brave 401/429/5xx is recorded on that request and the planner keeps going, so an expired `BRAVE_SEARCH_API_KEY` ships completed episodes full of reuse and concept cards rather than failing loudly. The evidence is `imageSearch.requests[].error` in the stored payload — check it before blaming the subject catalog or the ranking, and keep `strict` mode raising so tests and the smoke CLI still see the outage.
- **An abandoned episode is a sticky operator decision, and it guards exactly two RPCs.** `episode_video_visuals.abandoned_at` / `abandoned_reason` (all-or-nothing, enforced by `episode_video_visuals_abandoned_pair_check`) close an episode whose video work can never finish as designed — missing language lanes that were never enqueued and whose zh-Hant release already shipped, or a storyboard that cannot align against a shorter translation. `retry_episode_video_generation` and `retry_episode_video_render` call `assert_episode_video_not_abandoned` **before** the release fence, so the refusal names the closure instead of a version mismatch. Nothing else reads it: `enqueue_episode_video_visual` / `enqueue_episode_video` are deliberately unguarded, because re-posting the source URL is an operator asking for the work to be redone from scratch. Do not add the check there, and do not turn this into an `episode_videos.status` value — that CHECK constraint has four states and its completed rows must carry real media, so a fake completed lane would make the app play the wrong language and make the social gate believe three languages exist. Re-opening means clearing both columns.
- **The visual checkpoint resumes only what the DB says is the same job.** `parseVisualCheckpoint` requires the checkpoint's `visualVersion` and `sourceHash` to match the claimed row; `retry_episode_video_generation` clears it on `p_force_replan` or a version change and a trigger clears it whenever `visual_version`/`source_hash` change. A checkpoint that survives those events would resume a stale storyboard against a rewritten script, so extend the invalidation, never relax the match.
- **Failure diagnostics are written before `fail`, through their own RPC.** Changing `fail_episode_video_visual`'s signature instead would leave every failure between the Fly deploy and the `supabase db push` unrecorded (the row would be reaped without `last_error`). Keep `record_episode_video_visual_failure_diagnostics` separate.
- **Telegram `/retry`, `/status` and the `retry_video:` callback share the webhook's fast-ack contract.** Work runs in `process.nextTick`, replies go through `telegramIngestQueue.scheduleMessage`, and `callback_data` stays under Telegram's 64-byte limit (`retry_video:` + UUID = 48 bytes). Do not `await` Supabase inside the handler.
- **Tests target the Hono app directly via `app.request(...)`** (see `src/index.test.ts`). No HTTP server is started in test mode.
- **Fish Audio is the only TTS provider, and that is code-owned.** Only engines ending with `free` are allowed; current required configuration and runtime default are `FISH_AUDIO_ENGINE=s2.1-pro-free`. Reject paid engines before any request; never use paid fallback on errors, quota or outages. This applies to main audio, every classroom language and diagnostic auditions. Upgrade to newer provider-supported free versions by changing canonical env defaults, runtime defaults and tests together; free Fish synthesis needs no payment approval. `src/services/tts.ts` is a thin facade over `src/services/tts/fish-audio.ts`; there is no provider dispatch, no `TTS_PROVIDER` env, and no Google TTS. `getTtsConfig()` fails closed when `FISH_AUDIO_REFERENCE_ID` is missing rather than degrading to another voice. **Production narration always sends each complete text/chunk to Fish Audio unchanged, including zh/ja text that contains English terms. Do not split English terms into separate requests or splice them back into the surrounding narration:** doing so removes sentence context from TTS and produces unnatural prosody. The mixed-language audition utilities are diagnostic only and must never be wired into production routing. Adding a second provider means reintroducing dispatch deliberately — do not add a provider branch to keep some other change convenient.
- **OpenRouter model routing is explicit per workload, and `LLM_MODEL` is reserved.** Only Podcast Script (`generateScriptWithLLM`) and Editorial Title (`editorial-title.ts`, including the independent verifier and budget compression) call `getOpenRouterConfig` without a `model`, so only they use the paid `LLM_MODEL` primary. Every other workload — translation, language classroom, social copy, the visual subject catalog, concept-card copy and scene alignment — passes `OPENROUTER_FREE_MODEL` (`src/services/llm-model-fallback.ts`); transport failures still advance through the shared `LLM_FALLBACK_MODELS`. Free-router requests omit the `reasoning` override because some endpoints reject disabling reasoning (live canary, 2026-10-05); paid fallback candidates retain the caller's original reasoning options. When a request disables reasoning, only the exact HTTP 400 provider message `Reasoning is mandatory for this endpoint and cannot be disabled.` permits advancing to the next candidate (2026-10-06); do not enable reasoning automatically, replay this capability rejection, or generalize it to auth/config 4xx failures. This applies to Script and Editorial Title, including the verifier and compression. A new OpenRouter workload must choose explicitly, because the unqualified call silently buys the paid model; moving a workload onto `LLM_MODEL` is a cost decision for the owner.
- **`server.closeIdleConnections()` is the load-bearing wall for restart speed and drain semantics.** `bootstrap()`'s teardown does `server.close()` + `server.closeIdleConnections()` and awaits the `close` callback. Idle keep-alive sockets (Fly's 30 s health checks) would otherwise keep the Node event loop alive forever, forcing every `secrets deploy` restart to pay the full `kill_timeout = '300s'` even when idle (5 × ~302 s observed). `closeIdleConnections()` drops those idle sockets immediately so idle shutdown exits in seconds while in-flight ingest keeps draining via its own Supabase/R2/LLM/TTS handles until the next committed stage or the 300 s guard. Never add `process.exit()` in the teardown — it would abort that drain and recreate the silent-stall risk that `kill_timeout` deletion would have introduced.

Start the social daemon from the repository root with `pnpm ops --social`.

## Audio section invariant

Do not concatenate language classroom audio into the main episode audio.

The canonical contract (per-language classroom, refactored 2026-08) is:

- `episode_localizations.hls_url` / `r2_prefix` stores main article narration only.
- Each `language_classrooms` row owns its **own** monolingual `script` (target-language-only narration) and its **own** independently-synthesized `hls_url` / `r2_prefix`. This per-language HLS is the canonical classroom artifact, not `episode_localizations.classroom_hls_url`.
- `episode_localizations.classroom_hls_url` / `classroom_r2_prefix` is now a **derived** artifact: the per-language classroom MP3s are concatenated (in target order) into one combined HLS at zero extra LLM/TTS cost. New episodes still produce it so `completed`-status checks, RLS policies, video-eligibility checks, and pre-refactor app builds keep working unmodified. Never derive it any other way (e.g. re-synthesizing a combined script).
- The mobile app plays main + one classroom section per target language as sequential playback sections within the same logical episode (language "chips" inside the Classroom tab select which target). Older app builds that only know the combined URL keep working off the derived artifact.
- Main and classroom playback speeds are intentionally independent. Classroom defaults to 1.0x.
- For a localization with configured classroom targets (currently canonical `zh-Hant` targeting `ja` and `en`), `completed` means the main HLS, every required per-target classroom HLS, **and** the derived combined HLS all exist. A status value alone is not evidence that audio is complete.
- Missing classroom lessons/scripts, failed classroom TTS for any required target, failed classroom concatenation, or a missing per-target or combined classroom HLS must fail ingest. Never publish a successful main-only canonical episode as a fallback.
- **The missing-target predicate that drives content (re)generation must stay presence-based**: a `language_classrooms` row existing for a target — regardless of whether its `script` is populated — counts as "not missing." This is what guarantees a previously-published episode (whose rows predate the `script` column and are therefore `script: null`) is never regenerated or re-touched by this refactor. Only flip this to a script-completeness check if you intend to force regeneration of every already-published episode; do not do that silently.
- Script backfill (writing a blank `script` on an existing row) happens **only** inside the audio-synthesis path, and only when that localization's classroom audio is not yet ready. It is unreachable for an already-completed row, by construction — do not add a code path that can backfill a script for a row whose audio is already ready.
- A previously completed row missing the combined `hls_url`/`r2_prefix`, or any required per-target classroom HLS, is incomplete and must resume by generating only the missing pieces without regenerating the main narration.
- Per-target `hls_url`/`r2_prefix` checkpoints on `language_classrooms` exist for observability and API reads only — **they are not a skip condition**. A resumed/retried ingest re-synthesizes TTS and re-packages HLS for every required target even if some were already checkpointed from a prior attempt. This is an accepted request-count and latency trade-off on the free Fish engine, not a bug; do not add per-target skip-if-checkpointed logic without an explicit decision to do so.
- `upsertLanguageClassrooms`'s payload never includes `hls_url`/`r2_prefix` — only content columns (`script`, `one_liner`, `keywords`, `llm_*`). A content-only upsert (e.g. script backfill) must never clobber an existing per-target audio checkpoint; keep the upsert column list scoped to content when adding fields.
- Demote an invalid completed row before repair, and persist each uploaded audio section (main, each per-target classroom, and the derived combined) under `audio_generated` before advancing. Promote to `completed` only after the persisted row contains all required HLS URLs.
- Database compatibility fallbacks must never remove classroom media fields from a completed write. Feed/RLS/video eligibility must enforce the same dual-audio condition against the derived combined URL (old contract) while the per-language rows carry the canonical per-target URLs (new contract).

Never reintroduce `concatMainWithClassroomAudio` or equivalent logic that appends classroom audio into the main HLS. `combineClassroomAudio` (per-language MP3s -> one combined MP3, used only to build the derived combined HLS) is a distinct, still-legitimate function — do not confuse the two.

All tests must exercise the same fail-closed classroom audio invariant as production. Do not add test-only switches that make canonical classroom audio optional.

## Language classroom content invariant

The audio-section invariant above governs the HLS _artifacts_. This section governs the _content_ those artifacts carry. The content layer has no schema/DB enforcement, so it is guarded by `src/services/llm.classroom.strict.test.ts` and the independent `scripts/check-classroom-contract.mjs` gate (wired into `lint`).

- **Grounding is required.** The classroom lesson generator (`generateLanguageClassroomsWithLLM` in `src/services/llm.ts`) must receive the title **and** the full article text **and** the podcast script. `LanguageClassroomInput` carries `articleText` and `script`; `buildLanguageClassroomUserMessage` must include the `文章內容：` and `Podcast 講稿：` blocks; the `ensureLanguageClassrooms` call site (`src/services/ingest/audio-stage.ts`) must pass `localization.raw_text` and `localization.script`. Narrowing the prompt to the title alone is a content regression, not a simplification.
- **Keyword selection is concept-based and shared.** Keywords are the episode's core financial/crypto concepts chosen from the article and script (thinking in `zh-Hant`), not substrings of the title or `oneLiner`. Every target language teaches the same shared concept set (same count and order). `oneLiner` remains the title translation used only as the classroom opening line — it and `keywords` stay source-language UI metadata, separate from the per-target `script`; do not blank out `meaning` on a keyword, since the app's parser silently drops the whole keyword entry if `meaning` is blank.
- **Each target's `script` is a purely target-language narration, grounded in the same article and podcast script.** The LLM must generate one `script` per target (~1.5-3 min of spoken narration) that (a) uses **only** the target language — no mixed-language segments — and (b) is written from, and covers, the same article/script content and the same shared keyword set as that lesson's `oneLiner`/`keywords`. A lesson whose `script` is blank is dropped rather than published with silent/empty audio.
- **Contract changes need explicit product sign-off.** Changing the system prompt, the input contract, or the lesson shape is a product decision. Do not alter it as an incidental part of unrelated work, and never rewrite the strict/contract tests in the same change to make a narrowed prompt or a language-impure/ungrounded script pass.
- **App-side dual-section contract.** Main audio and one classroom section per target language are playback sections of one logical episode. The app (`apps/app`) must play them sequentially (main -> each target's classroom, in order) with independent per-section speed (classroom defaults to 1.0x); see `apps/app/src/integration/podcastSections.ts` and its tests. Dropping classroom playback, or collapsing per-language sections back into a single combined section, on the client is the app-side equivalent of a main-only fallback.

## Social release cohort invariant

**NON-NEGOTIABLE PRODUCT CONTRACT: an episode releases as one cross-platform cohort. Never schedule platforms independently.**

Changing this behavior requires explicit product approval. Do not rewrite this invariant or its contract tests as part of an optimization/refactor PR. Reach optimization may tune article-level frequency, article slots, copy, packaging, or lane allocation inside this contract; it may not redefine the release unit.

Optimization also obeys the [universal packaging contract](src/social/AGENTS.md#social-optimization-contract).

- **`episode_id` is the release cohort and transaction boundary.** A platform × language is only a durable lane inside that transaction. `src/social/cohort.ts`'s `resolveReleaseCohortLanes()` is the single lane-shape definition used by discovery and release logic.
- **Every pending lane of one episode shares exactly one `scheduled_at`.** `discoverAndEnqueue()` chooses one article slot via `nextReleaseSlot()` and `enqueueCohortJobs()` writes that timestamp to all active lanes. `SOCIAL_RELEASE_CADENCES` is backlog-aware at the article level: 0-9 wholly unpublished queued episodes use 4/day, 10-20 use 5/day, and 21+ use 6/day. The selected cadence applies to the whole queue, never to one platform; one article consumes one slot. Several articles may share a JST day; one article split across several times may not. Do not reintroduce `enqueuePlatformCohort`, `platformBudgetIndex`, `PLATFORM_PUBLISH_POLICY`, `nextBudgetSlot`, or an equivalent abstraction under another name.
- **Transport completion time is not scheduling.** Real API/browser calls are sequential and may finish seconds or a few minutes apart; that is still one daemon release cycle. A design that intentionally gives Rednote, Threads, X, or YouTube different hours/days is staggered scheduling and violates this contract.
- **A cohort enqueues only after all required media is ready, and every claimed cohort is re-checked before transport.** Missing required media holds the whole episode; never release a ready platform early. Follow [the social release readiness sequence](src/social/AGENTS.md) for required languages, slot selection, and pre-transport rechecks.
- **A pending lane is claimable only when `scheduled_at` and `next_attempt_at` are both due.** `claim_social_publish_batch` fences on both. Failed lanes preserve retry backoff; queued lanes aligned by cohort repair use the cohort timestamp for both columns.
- **Partial publication is exceptional recovery state, not steady state.** When any lane is already completed and a sibling remains unfinished, `listPartiallyPublishedCohorts()` fences `publishDueJobs()` to that `episode_id` through the existing `p_episode_id` RPC argument. If the remaining lane is still serving retry backoff, publish nothing else that tick. Finish the article before starting a fresh episode.
- **The fence must always be bounded.** "Unfinished" means a lane `claim_social_publish_batch` can still return, so `listPartiallyPublishedCohorts()` reads `attempt_count` and mirrors the RPC's `MAX_PUBLISH_ATTEMPTS` fence. A lane that has burned every attempt is dead, not unfinished: holding the fence on it would stop every other article forever rather than for one backoff, so it is surfaced as `blocked` by the queue summary and released from the fence. A fence that publishes nothing also logs that it is holding, because a silent hold is indistinguishable from an empty queue.
- **Never resend a successful lane during recovery.** Persisted `social_posts` is authoritative evidence that the lane is live. Reconciliation completes/repairs the durable job instead of calling transport again; post/job identity remains `(episode, platform, language)` for this duplicate guard.
- **Legacy/missed queue rows repair at article scope.** `alignPendingSocialReleaseCohorts()` runs before discovery. A completely unpublished legacy episode with staggered timestamps is serialized onto one article slot; an actually missed unpublished cohort moves together to the next article slot. Never fake-complete an unpublished lane because its time passed. `processing` rows are not mutated under a live lease, and failed rows keep later retry backoff.
- **Manual catch-up is one bounded operator exception, not a second scheduler.** `pnpm ops --social-once` acquires the same daemon pid lock, reconciles persisted `social_posts`, and releases at most one article cohort before exiting. It deliberately skips missed-slot alignment and the 09:00–23:00 watch window, but it still uses `claim_social_publish_batch`, so `next_attempt_at`, attempt ceilings, leases, the partial-release fence, media/copy barriers, and duplicate protection stay intact. Only when no overdue durable cohort is claimable may one discovery pass make the oldest fully-ready unscheduled article due immediately. Never make this mode drain the backlog or bypass retry/safety fences.
- **Publishing is fail-fast.** `publish.ts`'s `publishSocialPlatforms()` throws a `SocialReleaseFailureError` on the first transport, local-state, or `social_posts` telemetry failure; `daemon.ts` does the same if post-publish verification cannot find the row. Whichever lanes already published before the failure stay published; nothing after the failure runs this tick.
- **`reconcile`, `align schedules`, `discover`, and `publish` are fatal; only observational work may isolate.** Metrics, account/pre-publish snapshots, experiment reporting, and queue summary may fail independently. Release-shape failures propagate out of `runSocialDaemonTick()` so the entry point can report, notify, release the pid lock, and exit. One bounded exception: socket/DNS-layer transient network failures detected by `isTransientNetworkError` (`ETIMEDOUT` / `ECONNRESET` / `EAI_AGAIN` / `UND_ERR_*` / `fetch failed` / `socket hang up`) that are **not** a `SocialReleaseFailureError` are retried inside the main loop for up to 5 consecutive ticks — because the next tick's `reconcile` is already the correct recovery path for a Supabase blip before transport started. `SocialReleaseFailureError` and all other errors remain fatal, and this retry is not a watch runner. A second bounded exception: a `SocialCopyGenerationError` -- **and only that type** -- holds the article instead of killing the daemon. The release barrier for a missing/unfit transport title (`resolveTransportTitle` returning null) is a separate, equally non-fatal hold in the same `holdCohortsMissingCopy()`: it spends an attempt (max 8), holds that cohort and lets other episodes continue. All three copy attempts are spent before any transport, so nothing is live and nothing is unreadable, but the same three attempts fail identically after a restart: the claim RPC picks the same seed episode, the release path refunds the attempt it charged, and fatal there is an unbounded loop that never spends an attempt and never lets the next article through. `holdCohortsMissingCopy()` therefore fails those lanes with `Release held: …` (one attempt, retry backoff, visible `last_error`) and the tick continues. Do **not** widen the hold to a plain `Error` from the same call site -- a missing prompt file or unset OpenRouter config is a deployment fault that must stay fatal.
- **`social:daemon` must never be a watch runner in production.** `tsx watch` auto-restarting past a fatal release error defeats the failure contract. Keep `social:daemon` plain `tsx`; `social:daemon:watch` remains explicitly debug-only.
- **Queue summaries are article-level and prefer the `zh-Hant` title.** One article prints one release time plus its indented lanes. Do not let lane sort order choose a Japanese/English headline when a Chinese title exists.
- **Executable guards are intentionally redundant.** `src/social/daemon-release-cohort-contract.test.ts` covers shared timestamps, the all-media barrier, one-article slots, partial fencing, reconciliation order, and title preference. `src/social/release-cohort-store.test.ts` covers durable queue repair. `scripts/check-social-release-contract.mjs` is an independent CI gate that rejects per-platform scheduler entry points even if ordinary tests are rewritten. Changing the product contract requires changing these guards only with explicit product approval.
- **Rednote hashtags are platform topic entities, never literal `#` text.** `rednote-playwright.ts` types each tag into the TipTap editor, accepts the exactly-matching suggestion row (`#creator-editor-topic-container .item`), and verifies the resulting `a.tiptap-topic` inside the editor -- the same anchor is mirrored into a preview region, so an unscoped read counts every topic several times. A 「新建话题」 row is a rejection, not a candidate: accepting it creates a brand-new topic with no audience and an empty link, which is success-shaped and worth nothing. The query is converted to Simplified because topic search is script-sensitive and the two scripts are _different topics_ -- 「宏觀經濟」 had 8.3万 views against 「宏观经济」's 5.2亿. A tag with no matching topic is skipped **and backspaced out**, because Escape closes the popup but leaves the typed characters in the body as exactly the literal hashtag this replaced; if no tag attaches at all the publish fails at `attach_topics` rather than shipping a note with no topic. `PublishResult.hashtags` carries what actually attached and `record.ts` stores that, so telemetry never records a tag that was never on the note.
- **Best Title is editorial authority.** `episode_localizations.title` is the Simplified Chinese Best Title (4..60 generation guard, no 20-character target) and is article-grounded (product-approved 2026-10-09): the generator reads the source title and the full article (empty article text fails), returns a thesis and 3–5 differently angled candidates with at most three short article quotes each, and every candidate passes deterministic screens (`normalizeEditorialTitle` 4..60, `convertTextToZhCN`, not identical to the source after normalization, the Rednote risk lexicon `findSensitiveTerms`) and an independent verifier (temperature 0, zod-validated JSON, article wrapped as untrusted data, doubt means fail). Every substantive claim must be supported by the article, replacing the old 'only from the source title' rule; the #743 guardrails stay (no unsupported superlatives or rankings, numbers stay with their owner, coordination is not turned into either/or, quotes stay attributable, denial scope is not widened, claims are not generalized, named entities are not made generic, the subject is not hidden, no investment advice, predictions keep attribution and tone). **The mechanical noun gate must not be revived**: it once killed 輝達股票變成鏈上抵押品了, a 245-view title. Selection follows verification order: a candidate that fits Rednote's measure is chosen as-is, otherwise it is compressed (the compression prompt describes 全角计1、半角计0.5 and never names a platform; three candidates per request and up to three requests, each retry told the exact measured units of what it rejected because the model cannot count half-width units, then measure and lexicon, then the verifier checks thesis, entities, relations and no new claim); a candidate that cannot be compressed hands over to the next; with none left, one more round runs with the issues, then ingest fails closed (cost is recorded first). This uses the paid `LLM_MODEL` as an owner-authorized cost decision. The Rednote measure lives in `src/social/policy.ts` (printable ASCII 0.5, other BMP 1, emoji 2, rounded up, limit 20; measured on the live form 2026-10-09, which refuses to submit over the limit and never truncates). `title_variants["20"]` keeps its key but means the Rednote budget under that measure; readers revalidate it and reject `truncate`, and legacy `llm` variants (at most 20 code points) are a strict subset. YouTube has only a 100-code-point check and no variant. Mechanical truncation (`fitTitleToBudget`, `fitRednoteTitle`) is deleted and must not return. Title, variants, script and `title_provenance` (version, thesis, angle, at most three evidence quotes of 120 characters, candidates, rounds, verifierRejections, model, variantSource `ingest|repair|null`) persist atomically, and title and variants precede script generation. Social only reads stored variants; `resolveTransportTitle` never throws, and a null result makes the release barrier hold the cohort rather than fitting the title. Resume/repackage never regenerate titles. Operator repair is `node scripts/env/run.mjs --environment prod -- pnpm --filter @zapengine/podcast-pipeline titles:repair [--apply]` (dry-run by default): it rewrites only missing or invalid `title_variants["20"]` for fenced, completed, not-skipped zh-Hant localizations not yet published on Rednote, grounded in the article, with the conditional write `eq(id).eq(title)`; it never changes Best Title, script, TTS or video and never reposts. No platform audience, per-platform hook/thesis, learned headline, or social title LLM. English translation targets 100 characters, and an over-100 title on the final attempt fails closed (attempts 2→3) instead of being cut. `legacy_title_override` remains migration-only; new jobs leave it null.
- **A Rednote field is only written when the SPA's own state says so, never when the DOM does.** `inputValue()` on the title returns whatever was just written to it, so it cannot detect the real failure: a write landing while the form re-renders (which attaching topics and setting the declaration both cause) sets the DOM value and never reaches the model, and the note is created with `title: ""`. That shipped untitled notes for weeks behind a check that never went red. `writeTitle()` verifies against the field's own character counter (`.count-tip`, a descendant of the same `.input` block as the field, rendered as `11 / 20`, absent as a whole element while the model is empty -- all three measured against the live form on 2026-08-27) and rewrites up to three times before failing at `fill_title`. Do not replace that with a DOM read-back, and apply the same reasoning to any new field: verify against something the SPA renders from its own state. **The acceptance condition is that the counter exists and reads above zero -- never that it equals `Array.from(title).length`.** Rednote weights a half-width character at half a full-width one, so it counts `AI代理不等於公鏈繁榮？` (twelve code points) as `11 / 20`; an equality check made every title carrying Latin text or digits fail `fill_title` forever the first time it met the real form, and because `publish` is fatal that took the release cohort down and held every queued episode shut behind it. The empty-model bug this check exists for shows up as an _absent or zero_ counter, never as off-by-one, so the counting model was never something the publisher needed to know: the one extra condition is that the counted value may not exceed the SPA's own denominator (the over-limit form would refuse to submit anyway), and a disagreeing count is logged as `title_count_mismatch`, now compared with the `src/social/policy.ts` measure (`rednoteTitleUnits`, pinned by the live-form fixture `src/social/__fixtures__/rednote-title-counter-2026-10-09.json`); a missing counter stays fail-closed. Do not tighten this back to equality, and do not derive a test's fake counter from the publisher's own formula -- that tautology is exactly what let the equality check ship. `readTitleField()` is exported so the test runs the shipped traversal against the live form's markup in jsdom, and it is serialized into the page by `Locator.evaluate`, so it must stay free of imports, module constants, and calls to neighbouring helpers.
- **Every Rednote note declares itself as AI-synthesized.** `declareAiContent()` opens the 「添加内容类型声明」 select, picks 「笔记含AI合成内容」, and waits for the `.d-select-description` that proves it stuck; it fails the publish rather than logging and continuing, because a skipped declaration is invisible after the fact. This is a compliance step about how the video was made, and is unrelated to AI as a subject -- which is never a risk.
- **Rednote uses deterministic lexicon checks and writer prompt rules, never a topic blacklist.** `prompts/social/rednote-risk-rules.md` supplies all four investment-direction rules to the writer. `asset_allocation_advice` and `market_timing_advice` are caught by `lexicon/asset-allocation.ts` / `lexicon/market-timing.ts` during generation and by `assertRednoteCopySafe` before publishing (title, body and hashtags). The LLM semantic judge was removed on 2026-10-05; `political_market_speculation` and `strong_prediction_unattributed` now rely only on the writer prompt, with no machine gate. Do not answer a zero-view post by adding its subject (AI, Bitcoin, a named politician) to a term list — topics belong to the owner, and the AI note that also scored zero remains pinned as a passing fixture.

- **Guarding tests.** The social optimization section in `scripts/check-social-release-contract.mjs` also guards universal packaging. `daemon-release-cohort-contract.test.ts`, `release-cohort-store.test.ts`, `publish.test.ts`, `daemon-release-fatal.test.ts`, `daemon-reconcile-*.test.ts`, `daemon.test.ts`, `daemon-store-queue-snapshot-timing.test.ts`, `rednote-playwright.test.ts`, `publish-error.test.ts`, `lexicon/index.test.ts`, plus `scripts/check-social-release-contract.mjs`, are what would catch a regression on the social bullets above.

## Deployment gate and recovery

- The podcast lanes in [deploy-fly.yml](../../.github/workflows/deploy-fly.yml) and [env-apply.yml](../../.github/workflows/env-apply.yml) share a DB-backed gate fenced by `deployment_id` + `owner_token`: `open → draining → rolling_out → open`. Never interrupt an active render with rollout signals.
- Both lanes validate before they acquire the gate: deploy-fly.yml runs its verify script, and env-apply.yml runs a read-only `pnpm env:sync --target podcast-pipeline` dry run. A manifest or `validateProductionEnv` rejection must fail the job while the gate is still `open`, never fence it in `recovery_required` without a single write having happened. Keep any new pre-write check ahead of `prepare`.
- Drain is bounded to 100 minutes; the job timeout is 150 minutes. A drain timeout happens before rollout and reopens only the same owner's gate. Failure after rollout starts leaves `recovery_required`.
- A stale heartbeat never automatically reopens claims. Do not add automatic stale-unlock.
- The render-capacity reconciler reads the same gate and fails closed when it cannot read it; it must not wake capacity.
- Recover only with the exact deployment ID and release printed by the failed workflow, from the repository root:

  ```bash
  node scripts/env/run.mjs --environment prod -- node scripts/podcast-deployment-gate.mjs recover --deployment-id <uuid> --release <git-sha>
  ```

  Read-only inspection uses the service-role RPC `from_fed_to_chain.podcast_deployment_state()`.

- Migrations precede code rollout. Later migrations must preserve DB contracts used by the old release still draining; destructive schema changes wait until the compatibility window closes.
- `retryWasteUsd` is removed, not deprecated. `failedAttemptCostUsd` counts priced stages on failed parent runs. Confirmed waste is a lower bound: display `null` as `Unknown`, never `$0.00`, and totals as `≥ $x`.

- **PANews body imagery is required publisher input.** `panews.io` / `panewslab.com` and their subdomains (case-insensitive, trailing dots normalized) acquire article/figure images in publisher order and place them by paragraph semantics plus article position. These bypass decorative URL, small dimensions and perceptual similarity checks, but identical SHA-256 files and failed acquisitions/decodes are skipped. All publisher downloads finish before the first Brave request. Never restore a DOM-order scene cursor. Mandatory og lead ignores image fingerprint duplicates so checkpointed body twins cannot block a lead retry.
- **Scene density must respect translation alignment.** New plans target 2.5–6 seconds with at most 150 scenes including outro. Publisher image slots raise the content floor only within the time and sentence ceilings; content count must fit English and available Japanese sentence counts, reserving one translated sentence for packaged outro. Completed visuals keep their stored storyboard; force replan to apply new density.

- **Identity queries and quality gating are mandatory.** Never reintroduce deterministic or descriptive content-scene queries. Catalog-derived identity queries alone reach Brave; visualCue only ranks candidates. Checkpoints persist compact selections so resumed scenes participate in the same pre-upload quality gate as fresh scenes.
