# @zapengine/design-tokens

`tokens.json` owns Zap Pilot's v3 brand primitives: paper/night roles, five sleeves, materials, status grammar, typography and the 32-unit mark. Hosts select a mode; they do not redefine its palette.

Web hosts import `@zapengine/design-tokens/css/variables.css` and `css/status.css`. Native and renderers import `@zapengine/design-tokens/tokens`. Archivo Variable and Martian Mono Variable supply web typography. Expo and Satori resolve the ten packaged static instances through `fonts/static/*`; family names match each font's name table.

The thirteen type roles use pixel sizes and line heights, em tracking, weight and width axes. Use `sign-ink` for text. `sign` is reserved for primary actions, wallet identity, signing, focus, selection and the mark needle. Success uses ink plus a filled glyph; caution uses ink-2 with a dashed rule. Up/down express numeric movement. Alerts have their own semantic roles.

Edit the source and regenerate:

```bash
pnpm --filter @zapengine/design-tokens fonts
pnpm --filter @zapengine/design-tokens brand
pnpm turbo run build type-check lint test:coverage deadcode dup:check --filter=@zapengine/design-tokens
```

Font sources are pinned by commit and SHA-256. The brand generator outlines Archivo glyphs and emits all host copies from the same mark and role colors. Tests compare regenerated bytes and validate packaged font metadata. Keep generated TypeScript, CSS, fonts and brand outputs with their sources. See [BRAND.md](BRAND.md) for construction and usage.

Verbal identity is owned by `@zapengine/zap-pilot-story/brand`; the glyph generator mirrors its English strings. Use `fonts --glyphs` to regenerate brand outlines without rewriting static font instances. Slogan assets include the self-hosting status and outline `machine.` until Live.
